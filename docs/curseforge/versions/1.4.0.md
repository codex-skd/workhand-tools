<h2>v1.4.0 - Silent Anchor Tome, border color config, AoE mining fix (Minecraft 1.21.1)</h2>

<p>A new Chunk Anchor tome, a configurable border color, and a fix for an AoE mining direction
bug that could break an extra, unrelated block.</p>

<h3>Added</h3>
<ul>
<li><strong>Silent Anchor Tome</strong> (<code>silent_anchor_tome</code>): same chunk force-load
behavior as the Anchor Tome, but the Chunk Anchor's border corner lines stay hidden always,
regardless of the border mode setting. Crafted with an iron ingot instead of an amethyst shard.</li>
<li><strong>Chunk Anchor border color</strong> is now configurable
(<code>chunkAnchorBorderColor</code>) instead of being hardcoded to white — reuses the same
color list as the tape measure's line color.</li>
</ul>

<h3>Changed</h3>
<ul>
<li><strong><code>NEARBY</code> chunk border mode redesigned.</strong> Instead of a flat
20-block radius, it now shows the border corners whenever you're standing anywhere within the
same chunk column as the anchor, at any height above or below it.</li>
</ul>

<h3>Fixed</h3>
<ul>
<li><strong>Missing translations in Configured.</strong> Several COMMON config options
(pitch threshold, tree felling leaf distance, chunk border mode, and the new border color) were
showing as raw config keys instead of translated labels. Fixed across all 10 supported
languages.</li>
<li><strong>AoE mining direction bug.</strong> Moving your crosshair onto an adjacent block
while still mid-break on the original one could make the tool's area-mining pattern extend onto
that adjacent block instead of the direction you were actually digging in — most noticeable on
plain shovels and pickaxes, since area mining is on by default even at grade 1. The dig
direction is now captured the moment you start breaking a block and reused when the block
actually breaks, instead of being recomputed from wherever you happen to be looking at that
moment. Axes and hoes use separate mining logic and were never affected.</li>
</ul>
